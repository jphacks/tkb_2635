# 1-06 夜間利用の調査（東京23区内・20地点）

調査日: **2026年10月24日（日本時間）**。既存6地点と追加候補14地点。区ごとの網羅より、広場・草地・水辺など空を見渡せる可能性のある場所を優先した。
既存6地点の営業時間・入場可否をアプリへ反映した。追加候補14地点はこの調査表で管理する。変更はdevelop宛てのPRとして共有する。日次実行は既定ブランチへの反映・有効化後に開始する。

## 結果の見方

- **常時開園を確認**: 通常時の一般園地について、取得できた公式本文に根拠がある。園内施設・工事区域の開放まで保証しない。
- **時間制限あり**: 使える時間や場所を限定して確認した。新宿御苑の通常閉園後には入れない。
- **未確認**: 場所の特定や夜間利用の明記が不足、または根拠の本文を取得できなかった。`nightAccess` と入場確認日は `null` にした。
- 夜間入場と星の見やすさは別の項目。照明・樹木・周辺建物・立てる位置・観測できる方角は現地未確認。光の強さを仮の数値で埋めていない。

**常時開園の根拠あり12地点、時間制限あり2地点、未確認6地点。** 時間制限ありには、新宿御苑と若洲の海釣り施設を含む。

## 最初に検討する候補

水元公園・光が丘公園・舎人公園・篠崎公園を、夜間に使う場所の現地確認の候補とする。常時開園の公式根拠と広場等の紹介が揃っているためで、暗さや天体の見え方の順位ではない。
新宿中央公園・代々木公園・葛西臨海公園は既存地点として調査を続ける。新宿御苑は通常の夜間観測先から外す。若洲は21時までの海釣り施設に限って検討し、観測機材の利用可否・釣り利用との共存を管理者に確認する。

## アプリへ導入した内容

- 渋谷駅東口のデモ地点・荒川河川敷（船堀付近）は、`alwaysOpen: true` を取り下げ、`accessRules.unverified: true` と確認日 `null` を設定した。「入場可否は未確認」と表示し、推薦にはしない。閉園が確認できた地点とも区別する。
- 新宿中央公園・代々木公園・葛西臨海公園は通常の一般園地の常時開園を反映した。一部区域の規制は公園全体の閉園とは区別し、指定日の詳細画面に表示する。登録地点と規制区域との対応が未確認の間は「要確認」とする。
- 新宿御苑は、季節別の開園・閉園・最終入園時刻、月曜休園、祝日後の翌平日休園、年末年始、春秋の連続開園を反映した。最終入園の分を過ぎると、新規の入場先として推薦しない。入場済みの利用者の滞在判定とは異なる。
- 休園日は[内閣府の祝日CSV](https://www8.cao.go.jp/chosei/shukujitsu/syukujitsu.csv)を取得して2026〜2027年分を生成した。その範囲外の日付は「未確認」とする。臨時閉園・特別夜間営業・予約の空き状況は自動判定しない。
- 公式情報の確認日だけを更新して、不明な値を確認済みに変えることはしない。追加候補14地点の座標・標高・観測位置は未設定のままで、アプリへの新規登録は1-10の作業とする。

反映する方針は `app-access.json`、祝日は `holidays.json`。`scripts/apply_night_access.py` で既存6地点へ反映し、StarCoreの `SpotAccessRules` で判定する。従来のJSONでも読み込める省略可能な項目を追加し、地点ごとの判定を画面に書かない構成にした。

```bash
python3 scripts/apply_night_access.py          # 確認済みの方針と同梱データの照合
python3 scripts/apply_night_access.py --write  # 人が方針を更新した後の反映
```

## 毎日の公式情報確認

`.github/workflows/night-access.yml` は、反映後に毎日 **06:37（日本時間）** の実行を予定する。GitHub側の混雑で遅れる場合がある。現在は手元に用意した段階。
20地点すべてについて少なくとも1件、計27件の公式ページを自動確認する。ほかの7件は本文がHTTP 502/503となり、再試行しても取得できなかった補助資料で、手動参照と明記した。検索結果の案内だけでは確定値にしない。

- `sources.json`: 取得先・ページの識別名。手動参照には取得できない理由を付けた。
- `candidates.json`: 人が確認した判断・時間・対象範囲・出典・未確認事項。自動処理は書き換えない。
- `baseline.json`: 比較基準となる公式ページのURL・タイトル・本文とリンクの指紋（SHA-256）。公式本文そのものはリポジトリに複製しない。
- `scripts/check_night_access.py`: 公式本文・リンク・画像URLを基準と比較し、JSONとサマリーを出力する。

変更・初回・監視対象の削除・取得失敗があれば、Actionsを要確認の失敗状態にする。通常の変更と通信失敗はレポートで区別する。各実行の結果はサマリーと14日間保存する実行添付ファイルで確認できる。変更がなければ成功。`contents: read` の権限だけを使い、自動コミット・push・PR・アプリデータ更新は行わない。

監視は登録したページの本文・リンク・画像URLに限る。リンク先の記事本文すべて、同じURLのまま差し替わる画像/PDFの中身、SNSのみの告知、JavaScriptで後から表示される情報は検査しない。新宿中央公園の芝生閉鎖の既存告知は個別の監視先にも登録した。日次確認はその時点の差分であり、その後の急な閉鎖や現地の安全を保証しない。

### 手元での実行

Python 3.9以降、追加ライブラリ不要。通信なしテストと公式ページ確認は別のコマンド。

```bash
python3 -m unittest discover -s scripts/night_access_tests -v
python3 scripts/check_night_access.py --output /tmp/astera-night-access
```

変更の内容を出典で確認した後、比較基準を更新する場合だけ次を実行する。取得失敗が1件でもある場合は基準を書き換えない。

```bash
python3 scripts/check_night_access.py --accept-baseline --output /tmp/astera-night-access
```

基準更新後は、この別表と `candidates.json` の判断も人が確認する。未確認地点が自動で「利用可」に変わることはない。

### GitHubで開始するための条件

1. このワークフロー・Python処理・`docs/night-access/` のデータを、通常のPR手順で既定ブランチにも含める。作業ブランチに置くだけでは定期実行は始まらない。
2. Actionsでワークフローを有効にし、「1-06 夜間利用の公式情報確認」の手動実行を確認する。
3. 確認する人がActionsの失敗通知と添付ファイルを見られることを確かめる。専用APIキーやPR作成権限は不要。

日次確認はGitHub Actions上でまだ実行確認していない。1-06の既存6地点への導入を実施し、未確認の2地点は未確認のまま表示・推薦判定する。

日次実行の開始条件・時刻指定は[GitHub公式ガイド](https://docs.github.com/en/actions/reference/workflows-and-actions/events-that-trigger-workflows#schedule)、実行添付ファイルは[upload-artifactの公式説明](https://github.com/actions/upload-artifact/tree/v4)を参照。
