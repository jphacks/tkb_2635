# 国土地理院の標高で床面標高を入れる（task.md の 2-06）

全 43 地点の緯度経度で、国土地理院の標高 API（`https://cyberjapandata2.gsi.go.jp/general/dem/scripts/getelevation.php`）から地面の標高を取った。
取得日・URL・生の応答と、反映した結果は [gsi-elevation.json](gsi-elevation.json) にある。作り方は `scripts/gsi_elevation.py`。

```bash
python3 scripts/gsi_elevation.py fetch           # 取り直す（1 秒に 1 回、約 45 秒）
python3 scripts/gsi_elevation.py apply           # 反映案を表示するだけ
python3 scripts/gsi_elevation.py apply --write   # spots.json に反映
```

## 反映の決まり

- **地上の地点（公園・広場・河川敷）**: `floorElevation` = DEM の値。`floorElevationSource` に「国土地理院 DEM1A 2026-10-25」のように入れる
- **ただし、建物データ（`buildings.json`）のシーンの地盤標高と DEM の差が 2 m を超える地点は変えない**。建物の高さはシーンの地盤標高から測っているので、観測者だけ DEM に合わせると、建物との高さの関係が狂うため
- **展望台・屋上**: 公式の床の高さを確かめた地点だけ、「DEM ＋ 地上 ◯ m」か「海抜 ◯ m」にする（1-07、[observatory-heights.md](../facilities/observatory-heights.md)）
- 標高の出典 `hsrc` は API の返した値。23 区のほとんどは「1m（レーザ）」（DEM1A）、一部が「10m」（DEM10B）

## 要確認（DEM とシーンの地盤標高の差が 2 m を超え、変えなかった地点）

| 地点 | DEM [m] | シーンの地盤 [m] | 差 [m] | いまの床面標高 [m] | 考えられる理由 |
|---|---|---|---|---|---|
| 葛西臨海公園 | 7.9 | 3 | +4.9 | 3 | 代表点が盛土の園内で、シーンの地盤は床に合わせた設定値 |
| 舎人公園 | 10.8 | 4.0 | +6.8 | 10.8（もとから DEM） | 園内が周囲より高い。シーンの地盤は周りの建物の中央値 |
| 若洲海浜公園 | 15.7 | 6.0 | +9.7 | 6.0 | 埋立地の高台。シーンの地盤は周りの建物の中央値 |

この 3 地点は、建物データのシーンを作り直すとき（地盤を DEM に合わせる、または建物ごとの地盤を使う）に合わせて直す。
舎人公園は、床が DEM・建物がシーンの地盤（4 m）で、観測者が建物の基準より 6.8 m 高い状態がもとから続いている。

## 分かったこと

- 地上の 31 地点のうち 28 地点で DEM を反映した（そのうち 9 地点は値が同じで、出典だけ入った）。変化はほとんどが 1 m 以内。大きいのは新宿中央公園（40 → 35.5 m）、荒川河川敷（2 → 0 m）、押上（0 → -1.3 m）
- 渋谷駅東口 地上は 15 → 14.8 m（目の標高 16.3 m）。「地上では月が隠れ、SHIBUYA SKY では見える」判定は変わらない（`swift test` で確認）
- DEM は地面の標高で、舗装面・園路の実測値ではない。地点の座標が建物の上にあるとき、DEM は建物を除いた地面の値になる
